# Data model: TMASI v4 home

All data is static and lives in `tmasi-v4/src/content/`. Nothing is stored at run time.

## Office

| Field | Type | Rule |
|---|---|---|
| id | `eg` `de` `es` `ae` `us` | fixed |
| name | string | footer words, e.g. "Egypt Office" |
| address | string | footer words (as the live home and v3) |
| phone, tel | string | footer words; `tel` digits only |
| email | string | footer words; USA adds usa@tmasi.net from the contact page (his yes, 2026-10-01) |
| lat, lng | number | from the contact page's full address, city level |
| storyOrder | 0 to 4 | Egypt is 0; the rest as picked on the canvas |

| id | Pin position (contact page address) | lat, lng [assumed, city level; checked on a map at Stage A] |
|---|---|---|
| eg | Building 11, Airport Road, Hurghada | 27.178, 33.799 |
| de | Leopoldstraße 244, 80807 Munich | 48.170, 11.586 |
| ae | Dubai Silicon Oasis, Dubai | 25.120, 55.380 |
| es | Calle Pujades 362, 08019 Barcelona | 41.405, 2.205 |
| us | 401 E Jackson St, Tampa, FL 33602 | 27.948, -82.457 |

Validation: exactly five offices; no other pin may be drawn; the footer words are never replaced
by the contact page words (Germany differs between the two and keeps the footer version).

## Arc

| Field | Type | Rule |
|---|---|---|
| from | office id | always `eg` |
| to | office id | each of the other four, once |
| order | 1 to 4 | story order |
| drawMs, holdMs | number | from the motion he picks |

## Story beat (state machine of the hero)

`still` → `arriving` → `story` (Egypt lights, arcs draw one by one) → `idle` ⇄ `focus(office)`,
plus `paused` (off screen or hidden tab), `lost` (WebGL context lost: the still shows, and a restored
context rebuilds the scene and returns to `idle`) and `fallback` (no 3D, reduced motion, slow device).
`paused` returns to the state it left. `fallback` is final for the visit.

## Section text

`home.en.json` holds every visible sentence, keyed by section (`header`, `hero`, `about`, `relax`,
`values`, `mission`, `why`, `services`, `quote`, `hubs`, `news`, `partner`, `footer`). Generated by
`pull-content.mjs`; never edited by hand. `approved-labels.json` lists every label that is not on the
live site, each with his words and the date he approved it (v3 labels carried over: stats labels,
Global Operational Hubs, Quick Links, View Details, View All News, Read more, Latest News & Updates,
Ready to partner band, Get in Touch).

## Media asset (`media.json`, the media register)

| Field | Type | Rule |
|---|---|---|
| id | string | e.g. `relax-loop`, `icon-evacuation` |
| kind | `image` `loop` `film` `poster` `icon` `globe-still` `logo` | |
| section | section key | where it is used |
| source | `generated` `stock` `client` `built` `official` | |
| origin | text | the prompt file, stock URL or logo URL |
| licence | text | e.g. "Pexels licence", "CC0", "his Google account output" |
| files | list | one per variant (desktop, phone, 2x), with pixel size and KB |
| alt | string | describes what is shown; never adds a claim |
| status | `draft` `approved` `rejected` | only `approved` may ship |

Validation: every file within its budget (contracts/media-contract.md); no `poster` taken from a
video; no `approved` asset without his yes.

## Device composition

Each section has a `desktop` and a `phone` variant (spec FR-009). The pair is recorded from the
canvas picks, so Stage E builds exactly what he chose for each device.
